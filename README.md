# 💗 情侣网站 · 我们的家

一份用心准备的小惊喜 —— 纯 HTML / CSS / JavaScript 编写的情侣网站，
**零依赖、可离线运行**，双击 `index.html` 即可使用，也可以部署到任意静态托管平台（GitHub Pages / Netlify / 服务器）分享给 TA。
自带 **PHP 管理员后台**（部署到支持 PHP 的主机时启用）：登录后即可在线修改全部配置与数据，
留言板 / 手写情书 / 相册照片自动转为**服务器存储（跨设备共享）**，更新网站**永不丢失自定义内容**。

参考 GitHub 上开源情侣/纪念日项目（[romantic-gift-web](https://github.com/YU123-ZZZ/romantic-gift-web)、[Anniv-Project](https://github.com/GalihBimaa/Anniv-Project)）的长处，融合了：解锁仪式、实时恋爱计时、照片墙、时光轴、纪念日倒计时、情书、许愿瓶、默契问答游戏、内置音乐盒、管理员后台。

## 🌐 部署到服务器（在线访问）

### 第一步：构建

项目根目录运行（需要 Python 3）：

```bash
python tools/build.py
```

会在项目里生成 `dist/` 目录，**部署时上传 dist/ 里的内容**。构建脚本会自动给所有
CSS/JS/图片引用加上内容版本号（`style.css?v=3f9a2b1c`）：

- 改了代码 → 版本号自动变 → 浏览器必定拉新文件（部署后更新即时生效）
- 没改的文件 → 版本号不变 → 浏览器复用缓存（省流量、加载快）

> 不运行构建脚本直接传整个文件夹也能用，只是改代码后访客浏览器可能因缓存看不到更新
> （解决方法是手动强刷或等缓存过期）。

### 第二步：选择部署方式

**方式一：GitHub Pages / Netlify / Vercel（免费，推荐新手）**
把 `dist/` 内容推到仓库或用拖拽上传，平台自动配好 HTTPS。

**方式二：自有服务器（Nginx）**
1. 把 `dist/` 内容上传到服务器，如 `/var/www/love/dist`
2. 参考 `deploy/nginx.conf`，填进你的 Nginx 配置（或宝塔面板 → 网站 → 配置文件），
   记得改 `server_name` 和 `root`
3. 配置里已含：gzip 压缩（体积省 60%+）、静态资源 30 天长缓存、
   HTML 不缓存（更新即时生效）、安全头

**方式三：虚拟主机 / Apache**
把 `dist/` 内容上传到网站根目录，再把 `deploy/.htaccess` 也传上去（已配好压缩和缓存）。

> 💡 **想要管理员后台 + 服务器存储（留言板/情书/照片跨设备共享）？**
> 需要主机支持 **PHP**（如 InfinityFree 免费空间）。部署后访问 `/admin/` 首次创建管理员账号即可。
> 纯静态平台（GitHub Pages 等）不支持 PHP，后台自动不可用，网站退回纯静态模式（留言板等存本机）。

### 第三步（可选）：分享卡片

7 个页面已带 `og:title` / `og:description` 标签，链接分享到微信/QQ 会显示标题和简介。
想要带图片的分享卡片，在页面 `<head>` 里加一行（换成你的完整域名）：

```html
<meta property="og:image" content="https://你的域名/assets/img/photo-1.svg">
```

### 常见问题

- **后台保存了配置，前台还是旧内容？** 前台页面**刷新一次**（Ctrl+F5 / 手机下拉刷新）即可。
  配置接口带 `no-store` 头不会被缓存；若刷新后仍显示旧内容，用无痕窗口打开验证。
- **部署后改了 config 还是旧内容？** 重新运行 `python tools/build.py` 再上传，
  或让 TA 强刷一次页面（版本号已变的话刷新即新）。
- **图片/音乐不显示？** 确认文件名大小写与 `config.js` 里一致，路径以 `assets/` 开头。
- **需要 HTTPS？** GitHub Pages / Netlify 自带；自有服务器用
  `certbot --nginx` 一键申请免费证书，然后在 `deploy/nginx.conf` 里打开注释的 ssl 段落。

## ✏️ 如何改造成你们自己的

> ⭐ **第一步：把名字改成真的** —— 网站当前用占位名「待定A / 待定B」。
> **只改 `names.boy` / `names.girl`（或在管理员后台"基本设置"里改）一处即可，全站自动同步**：
> 生日标题、情书署名、默契问答选项等所有引用名字的地方都会自动跟随，无需逐处修改。
>
> **在一起的日期同理**：改 `startDate` 后，**相恋100天、相恋一周年、第一次相遇的日期自动计算**，
> 不用手填。全部改完刷新页面即可，无需动其他文件。

**所有内容都集中在 `assets/js/config.js` 一个文件里**（默认值），改完刷新即生效；
使用管理员后台修改时，修改内容存在服务器 `data/config.json`，会自动覆盖这里的默认值：

```js
names:      你们的名字（导航、主页、标题都会跟着变；其他所有引用名字的地方自动同步）
startDate:  在一起的日期（主页计时、纪念日都基于它；100天/一周年/第一次相遇的日期自动算）
password:   解锁密码（留空 "" 则取消密码，直接进入）
slogan:     主页大标语
greeting:   主页问候语（留空 "" 自动按时段问候"早上好…"，可写固定句子）
messages:   情话轮播（想加几句就多加几句）
homeCards:  主页六个介绍卡片
anniversaries: 纪念日列表（"05-20" 表示每年都过，"2023-08-28" 表示一次性；
               农历生日加 lunar: true，date 写农历月-日如 "8-15"，
               闰月生日写 "闰4-15"（自动找下一个有该闰月的年份））
timeline:   时光轴事件（date / icon / title / text；date 写未来日期会显示"即将到来"样式）
gallery:    相册照片（src / cat 分类 / cap 说明）
letters:    情书（date / title / body / sign）
wishes:     许愿瓶（title / text）
quiz:       默契问答（q 题目 / opts 选项 / a 正确答案下标 0 开始）
truthDares: 真心话卡片题库（抽一张轮流回答）
compatQuiz: 默契度测试题（q 题目 / opts 选项，没有标准答案，
            两人各答一遍，逐题对比算默契百分比）
```

**自动计算与自动同步**（不用手填的部分）：

- 纪念日/时光轴条目加 `auto` 标记即可自动算日期，date 不用写：
  - `auto: "start"` —— 等于在一起的日期（如"第一次相遇"）
  - `auto: "days100"` —— 在一起第 100 天（任意天数，如 days500）
  - `auto: "year1"` —— 在一起一周年（任意周年，如 year2）
  - 后台表单里这些日期显示为灰色（自动），改 `startDate` 后自动更新
- 所有文案里的「待定A / 待定B」会自动替换成 `names` 里的真名，
  手动改过、不含占位名的地方不受影响

### 放你们的照片

把照片复制进 `assets/img/`，然后改 `config.js` 里 `gallery` 的 `src` 即可：

```js
{ src: "assets/img/photo-1.jpg", cat: "旅行", cap: "第一次旅行的海边" },
```

照片建议宽度 800px 以上；占位图会自动被替换，无需动其他代码。

### 手写情书 & 留言板 & 相册添加照片（存在哪）

部署到支持 PHP 的主机后，「写新情书」「悄悄话留言板」和「相册里添加的照片」都保存在**服务器**
（`data/content.json` + `assets/img/uploads/`），**跨设备共享**：TA 在自己手机上写的话，你打开就能看到；
管理员在后台可以查看/删除。服务器不可用（或纯静态平台）时自动降级为浏览器本机存储，不会报错。
浏览器里已有的旧数据会在下次打开时**自动迁移到服务器**（uid 去重，不会传两遍）。

> 小游戏最高分与默契度答案仍保存在各人设备（设计如此，两人共用一个设备作答）。

### 换背景音乐（可选）

网站自带一个用 WebAudio 合成的轻音乐盒旋律，不需要任何音频文件。
如果想用你们自己的歌：把 `music.mp3` 放进 `assets/music/` 目录，刷新后自动优先播放它。

## 🔐 管理员后台（PHP 主机可用）

1. 浏览器打开 `https://你的域名/admin/`
2. **首次访问**进入安装页：设置管理员用户名和密码（页面会自检服务器可写性）
3. 登录后可以：
   - **基本设置**：名字 / 在一起日期 / 解锁密码 / 标语 / 问候语
   - **情话与卡片 / 纪念日与时光轴 / 情书与心愿 / 题库与真心话**：全部列表式编辑，支持增删、上下移动
   - **相册管理**：直接上传照片（自动压缩、存入服务器）、改分类与说明、删除；可管理访客上传的照片
   - **留言与手写情书**：查看 / 删除服务器上的内容
   - **备份与恢复**：一键下载全部数据（配置+留言+情书+照片记录+管理员账号），随时可恢复
   - **账号设置**：修改密码；高级模式可直接编辑整份 JSON
4. 保存后全站**立即生效**，无需重新构建/上传

安全设计：管理员密码用 `password_hash` 加盐存储；登录失败 5 次锁 10 分钟；
`data/` 目录对浏览器完全不可见（.htaccess 拒绝访问）；上传的照片只允许图片格式且禁用脚本执行。

## 🔄 更新部署（不破坏服务器自定义内容）

> ⚠️ **最重要的一条**：以后更新网站，**不要**用 FileZilla 之类"镜像同步/删除多余文件"的方式
> 上传整个目录 —— 那会把服务器上的自定义内容（后台配置、留言、照片）全部删掉！

更新请统一用仓库自带的部署脚本（需要 Python 3，凭据文件放仓库外）：

```bash
python tools/deploy.py --creds "我的服务器\服务器.txt"
```

脚本会：
1. 自动重新构建 `dist/`（版本号自动变化，访客强制拉新文件）
2. 只上传 `dist/` 清单内的文件，**绝不删除远程任何文件**
3. **永远跳过以下保护路径**（它们只属于服务器，由管理员后台维护）：
   - `data/` —— 后台的全部自定义数据（配置/留言/情书/照片记录/管理员账号）
   - `assets/img/uploads/` —— 上传的照片
   - `assets/img/*.jpg / .jpeg / .png / .webp` —— 直接放进服务器的真实照片
   - `assets/music/music.mp3` —— 背景音乐
4. 每次同步 `data/.htaccess` 与 `assets/img/uploads/.htaccess` 保护模板（幂等）

原则：**凡是被上传覆盖的文件 = 可替换的"程序"；自定义内容只存在于 `data/` 和 `assets/img/uploads/`**。
照片如果不想走后台上传，也可以手动 FTP 传进 `assets/img/`（不要放仓库里，构建会被跳过）。
