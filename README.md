# 💗 情侣网站 · 我们的家

一份用心准备的小惊喜 —— 纯 HTML / CSS / JavaScript 编写的情侣网站，
**零依赖、可离线运行**，双击 `index.html` 即可使用，也可以部署到任意静态托管平台（GitHub Pages / Netlify / 服务器）分享给 TA。
自带 **PHP 管理员后台**（部署到支持 PHP 的主机时启用）：登录后即可在线修改全部配置与数据，
留言板 / 手写情书 / 相册照片自动转为**服务器存储（跨设备共享）**，更新网站**永不丢失自定义内容**。

参考 GitHub 上开源情侣/纪念日项目（[romantic-gift-web](https://github.com/YU123-ZZZ/romantic-gift-web)、[Anniv-Project](https://github.com/GalihBimaa/Anniv-Project)）的长处，融合了：解锁仪式、实时恋爱计时、照片墙、时光轴、纪念日倒计时、情书、许愿瓶、默契问答游戏、内置音乐盒、管理员后台。

## 🚀 快速开始

1. 双击 `index.html`
2. 输入密码（默认 `520520`；**部署到 PHP 主机后以服务器 `data/config.json` 的 `password` 为准**），点击「开启我们的世界」
3. 随意浏览！

> ⚠️ **密码以服务器为准**：部署到 PHP 主机后，解锁密码存放在服务器 `data/config.json` 的
> `password` 字段，可能与这里的默认值 `520520` 不同（在后台「基本设置」里改过就是改过的值）。
> 如果输入后提示"密码不对"，说明输的不是服务器上的那个值 —— 见下方「忘了密码怎么办」。
> 前端 `assets/js/config.js` 里的 `password` 只在**纯静态托管**（无 PHP）时生效。

> 想分享给 TA：把整个 `love` 文件夹放到 GitHub Pages / Netlify / 任意静态服务器即可，
> 直接用 `https://你的域名` 打开。
>
> **密码强度取决于部署方式**：
> - 部署到**支持 PHP 的主机**（推荐，如 InfinityFree）→ 密码由服务器校验，成功后下发 HttpOnly Cookie，
>   所有内容接口与照片都要求这个 Cookie，**直接抓接口/猜照片地址都拿不到内容**（真门禁）。
> - 纯静态托管（GitHub Pages 等，无 PHP）→ 密码只是前端的"仪式感"，防不住懂技术的人；
>   此时请把网站地址当作半公开的，别放太私密的东西。

## 🔒 解锁密码是真的门禁（PHP 主机）

老版本的密码只在前端 `index.html` 里比对，任何人直接请求 `/api/config.php` 就能拿到留言/情书/照片。
现在改成服务端校验：

1. 解锁页把密码 `POST` 给 `api/unlock.php`（密码存在服务器 `data/config.json`，**绝不下发给前端**）；
2. 校验通过 → 下发 HttpOnly Cookie `love_gate`（HMAC 签名 + 30 天有效期）；
3. 所有内容接口（`api/content.php`、`api/daily.php`、`api/compat.php`）与照片代理 `photo.php`
   都先检查这个 Cookie，未解锁一律 401 / 403；
   **配置注入 `api/config.php` 同样分级**：未解锁时只下发 `names`（解锁页显示名字用），
   情话/相册/情书/时光轴/纪念日/题库等私密配置必须解锁后才注入 —— 直接看源码也拿不到；
4. 失败按 IP 计数：**10 次失败锁 10 分钟**；
5. 在后台改了解锁密码 → 签名密钥轮换，**所有旧 Cookie 立即失效**（需要重新解锁一次）。

> **降级态不会退回前端默认密码**：如果 `api/config.php` 的注入被主机防火墙/WAF 拦掉
> （页面右上角能看出是默认文案），解锁页会先探测一次 `api/unlock.php`：
> 探测期间**输入框和按钮都禁用**，按回车也不会进；探测不到就按"服务器模式"处理，
> 把密码交给服务器判定，绝不拿 `config.js` 里的默认值 `520520` 做比对。
> 只有确认接口是 404（GitHub Pages 这类**没有 PHP** 的纯静态托管）才沿用前端密码。

> 照片不再能直链：`assets/img/uploads/` 与 `assets/img/*.jpg` 被 `.htaccess` 拒绝，
> 只能通过根目录 `photo.php` 代理读取（它先校验解锁 Cookie）。纯静态托管没有 PHP，
> 会自动退回原来的直链方式。
>
> 忘了密码怎么办：直接在服务器上编辑 `data/config.json` 的 `password` 字段（或删除该字段=不再需要密码）。

### 不想被搜索引擎收录

私密小站不该出现在搜索结果里，本项目已经做了三层：

- `robots.txt`：挡 `/admin/`、`/api/`、`/data/`、`/lib/` 与常见 AI 爬虫；
  **故意不写 `Disallow: /`** —— 因为 Google 官方说明「被 robots.txt 拦住的页面读不到 noindex，反而可能留下无摘要的链接」。
- 每个页面 `<meta name="robots" content="noindex,nofollow,noarchive">`。
- `.htaccess` / `nginx.conf` 里 `X-Robots-Tag: noindex, nofollow, noarchive` 响应头
  （对图片、接口也生效，比 meta 覆盖面更广）。

真正拦住人的仍然是上面那把"真门禁"，而不是 robots.txt。

## 🌐 部署到服务器（在线访问）

### 第一步：构建

项目根目录运行（需要 Python 3）：

```bash
python tools/build.py
```

会在项目里生成 `dist/` 目录，**部署时上传 dist/ 里的内容**。构建脚本会自动给所有
CSS/JS/图片引用加上内容版本号（`style.css?v=3f9a2b1c`）：

- 改了代码 → 版本号自动变 → 浏览器必定拉新文件（部署后更新即时生效）
- 没改的文件 → 版本号不变 → 浏览器复用缓存（省流量、加载快）

> 不运行构建脚本直接传整个文件夹也能用，只是改代码后访客浏览器可能因缓存看不到更新
> （解决方法是手动强刷或等缓存过期）。

### 第二步：选择部署方式

**方式一：GitHub Pages / Netlify / Vercel（免费，推荐新手）**
把 `dist/` 内容推到仓库或用拖拽上传，平台自动配好 HTTPS。

**方式二：自有服务器（Nginx）**
1. 把 `dist/` 内容上传到服务器，如 `/var/www/love/dist`
2. 参考 `deploy/nginx.conf`，填进你的 Nginx 配置（或宝塔面板 → 网站 → 配置文件），
   记得改 `server_name`、`root` 和 `fastcgi_pass`
3. 配置里已含：gzip 压缩、静态资源 30 天长缓存、HTML 不缓存、安全头，
   以及 **`/data/` 与 `/lib/` 的拒绝规则**（Nginx 不读 `.htaccess`，这段千万别删，
   否则 `data/admin.json`（密码哈希）、`data/content.json`（私密留言）会被直接下载）
4. 配置里的 PHP 段是必需的（后台与接口都是 PHP）；宝塔面板会自动生成 PHP 段，
   可以只粘贴上面的 `location` 规则

**方式三：虚拟主机 / Apache**
把 `dist/` 内容上传到网站根目录，再把 `deploy/.htaccess` 也传上去（已配好压缩和缓存）。

> 💡 **想要管理员后台 + 服务器存储（留言板/情书/照片跨设备共享）？**
> 需要主机支持 **PHP 7.3+**（如 InfinityFree 免费空间）。部署后访问 `/admin/` 首次创建管理员账号即可。
> 纯静态平台（GitHub Pages 等）不支持 PHP，后台自动不可用，网站退回纯静态模式（留言板等存本机）。

### 第三步（可选）：分享卡片

7 个页面已带 `og:title` / `og:description` 标签。想加图片卡片可以在 `<head>` 里加：

```html
<meta property="og:image" content="https://你的域名/assets/img/photo-1.jpg">
```

> ⚠️ 但要注意：**InfinityFree 会 403 掉社交平台爬虫**（facebookexternalhit / Twitterbot 等），
> 所以在免费空间上链接预览的图片基本出不来（官方论坛确认无解，只有搜索引擎爬虫在白名单）。
> 想要真正的"分享卡片"，更靠谱的做法是用首页的**「🎁 生成纪念卡」**：直接生成一张竖版 PNG，
> 保存下来发微信 / 发朋友圈都行，不依赖任何爬虫。

### 常见问题

- **后台保存了配置，前台还是旧内容？** 前台页面**刷新一次**（Ctrl+F5 / 手机下拉刷新）即可。
  配置接口带 `no-store` 头不会被缓存；若刷新后仍显示旧内容，用无痕窗口打开验证。
- **部署后改了 config 还是旧内容？** 重新运行 `python tools/build.py` 再上传，
  或让 TA 强刷一次页面（版本号已变的话刷新即新）。
- **图片/音乐不显示？** 确认文件名大小写与 `config.js` 里一致，路径以 `assets/` 开头。
- **需要 HTTPS？** GitHub Pages / Netlify 自带；自有服务器用
  `certbot --nginx` 一键申请免费证书，然后在 `deploy/nginx.conf` 里打开注释的 ssl 段落。

## ✏️ 如何改造成你们自己的

> ⭐ **第一步：把名字改成真的** —— 网站当前用占位名「待定A / 待定B」。
> **只改 `names.boy` / `names.girl`（或在管理员后台"基本设置"里改）一处即可，全站自动同步**：
> 生日标题、情书署名、默契问答选项等所有引用名字的地方都会自动跟随，无需逐处修改。
>
> **在一起的日期同理**：改 `startDate` 后，**相恋100天、相恋一周年、第一次相遇的日期自动计算**，
> 不用手填。全部改完刷新页面即可，无需动其他文件。

**所有内容都集中在 `assets/js/config.js` 一个文件里**（默认值），改完刷新即生效；
使用管理员后台修改时，修改内容存在服务器 `data/config.json`，会自动覆盖这里的默认值：

```js
names:      你们的名字（导航、主页、标题都会跟着变；其他所有引用名字的地方自动同步）
startDate:  在一起的日期（主页计时、纪念日都基于它；100天/一周年/第一次相遇的日期自动算）
password:   解锁密码（留空 "" 则取消密码，直接进入）
slogan:     主页大标语
greeting:   主页问候语（留空 "" 自动按时段问候"早上好…"，可写固定句子）
messages:   情话轮播（想加几句就多加几句）
homeCards:  主页六个介绍卡片
anniversaries: 纪念日列表（"05-20" 表示每年都过，"2023-08-28" 表示一次性；
               农历生日加 lunar: true，date 写农历月-日如 "8-15"，
               闰月生日写 "闰4-15"（自动找下一个有该闰月的年份））
timeline:   时光轴事件（date / icon / title / text；date 写未来日期会显示"即将到来"样式）
gallery:    相册照片（src / cat 分类 / cap 说明）
letters:    情书（date / title / body / sign）
wishes:     许愿瓶（title / text）
quiz:       默契问答（q 题目 / opts 选项 / a 正确答案下标 0 开始）
truthDares: 真心话卡片题库（抽一张轮流回答）
compatQuiz: 默契度测试题库（q 题目 / opts 选项，没有标准答案；
            内置 30 题，每次发起随机抽 10 题，双方答同一套）
dailyQuestions: 每日一问题库（纯文本数组，内置 30 题；每天按日期轮一题，
            双方看到同一题，都答完才互见答案）
```

**自动计算与自动同步**（不用手填的部分）：

- 纪念日/时光轴条目加 `auto` 标记即可自动算日期，date 不用写：
  - `auto: "start"` —— 等于在一起的日期（如"第一次相遇"）
  - `auto: "days100"` —— 在一起第 100 天（任意天数，如 days500）
  - `auto: "year1"` —— 在一起一周年（任意周年，如 year2）
  - 后台表单里这些日期显示为灰色（自动），改 `startDate` 后自动更新
- 所有文案里的「待定A / 待定B」会自动替换成 `names` 里的真名，
  手动改过、不含占位名的地方不受影响

### 放你们的照片

把照片复制进 `assets/img/`，然后改 `config.js` 里 `gallery` 的 `src` 即可：

```js
{ src: "assets/img/photo-1.jpg", cat: "旅行", cap: "第一次旅行的海边" },
```

照片建议宽度 800px 以上；占位图会自动被替换，无需动其他代码。

### 手写情书 & 留言板 & 相册添加照片（存在哪）

部署到支持 PHP 的主机后，「写新情书」「悄悄话留言板」和「相册里添加的照片」都保存在**服务器**
（`data/content.json` + `assets/img/uploads/`），**跨设备共享**：TA 在自己手机上写的话，你打开就能看到；
管理员在后台可以查看/删除。服务器不可用（或纯静态平台）时自动降级为浏览器本机存储，不会报错。
浏览器里已有的旧数据会在下次打开时**自动迁移到服务器**（uid 去重，不会传两遍）。

> 「只能删自己发的」由服务器判定：每个浏览器第一次访问时服务端会发一个 **HttpOnly Cookie** 作为身份，
> 前端拿不到也伪造不了；如果浏览器禁用了 Cookie，就看不到自己内容的删除按钮（管理员后台仍可删）。
> 所有写入都走加锁读改写，两个人同时操作不会丢数据。

> 小游戏最高分保存在本机；**默契度测试结果存在服务器**（`data/compat.json`），
> 回合制：一人发起（随机抽 10 题）→ 答完等对方 → 对方打开游戏页**自动匹配**到等待中的回合直接作答
> （同一台设备可点"把手机给 TA"接力，无需配对码）→ 双方都答完才显示逐题对比与默契百分比。
> 完成的回合进入历史可回顾，管理员后台可查看/删除。

### 时间胶囊（写给未来的信）

在「情书」页底部：写一封信、选一个**开启日期**，封存后正文只存在服务器上。

- 开启日之前，**标题只给作者自己看，正文对任何人都不可见** —— 不是前端藏起来，
  而是服务端 `content_view()` 直接把字段剥掉，刷新、看源码、抓接口都拿不到；
- 到期当天（服务器时区固定 `Asia/Shanghai`）自动解锁，卡片从 🔒 变成 📖；
- 可以删掉自己写的胶囊（含未到期的）；管理员后台能看到全部（含未到期内容）并删除；
- 服务器不可用时降级为本机存储 —— 这时到期判断只能靠本机时间，只是兜底。

### 每日一问

首页每天一道题，**双方看到同一题**（题号 = 在一起的天数 % 题库长度），
**两个人都答完才能看到对方的答案**：

- 我只答了、TA 没答 → 我看到"等 TA 回答"；
- TA 答了、我还没答 → 我连"TA 答了什么"都拿不到（服务端不下发），但会提示"TA 已回答"；
- 记录存在 `data/daily.json`，按日期分桶，最多保留最近 400 天；后台可查看/整日删除；
- 题目在后台「题库与真心话 → 每日一问」里增删。

### 纪念日一键导入手机日历（.ics）

纪念日页顶部有「📅 一键导入手机日历」，每张卡也有「加入日历」。下载的 `.ics` 文件里：

- 全天事件（`DTSTART;VALUE=DATE`，绕开时区问题），每年重复用 `RRULE:FREQ=YEARLY`；
- **农历生日与 2 月 29 日会展开成未来 10 年的离散事件**（各客户端对这类 RRULE 处理不一致）；
- 每条事件带 4 个提醒：提前 7 天 / 3 天 / 1 天 / 当天上午 9 点；
- 导入一次就长期有效，提醒由手机系统日历负责 —— 这样"纪念日"才算真的能被记住。

> **为什么是"下载导入"而不是"订阅"**：订阅源需要日历 App 自己去抓取你的网址，
> 而 InfinityFree 的浏览器安全系统会拦掉所有非浏览器请求（日历 App 只会拿到一张挑战页），
> 所以订阅在这台主机上不可用。导入的本地事件反而可以自由改提醒，更可靠。
> 各平台导入方法见页面里的「怎么导入？」。

### 浅色 / 深色 / 跟随系统

导航栏右上角的 🌗 / ☀️ / 🌙 按钮三态切换，选择记在浏览器里；
`<head>` 里先执行 `assets/js/theme.js` 再加载样式，所以**不会出现首屏白闪**。
也可以用 `?theme=dark` 这样的链接参数强制主题（方便分享一个指定主题的链接）。

### 换背景音乐（可选）

网站自带一个用 WebAudio 合成的轻音乐盒旋律，不需要任何音频文件。
如果想用你们自己的歌：把音频命名为 `music.dat` 放进 `assets/music/` 目录，
刷新后自动优先播放它。（文件名故意不用 `.mp3`：免费主机会给音频响应强加
「禁止缓存」，每次翻页都要重新下载；`.dat` 能被浏览器正常缓存 30 天，
翻页秒出声，播放不受影响。）

**码率别贪高**：免费主机对大文件响应很慢（本站实测 7–13KB/s ≈ 56–104kbps），
码率高于链路带宽就会边下边卡。建议压到 **64kbps 单声道**（约 8KB/s），
`assets/music/说明.txt` 里有现成的 ffmpeg 命令。整曲比截取片段大得多，
慢链路上首次出声要等一会儿（这时右下角按钮会闪动表示在加载）。

## 🔐 管理员后台（PHP 主机可用）

1. 浏览器打开 `https://你的域名/admin/`
2. **首次访问**进入安装页：设置管理员用户名和密码（页面会自检服务器可写性）
3. 登录后可以：
   - **基本设置**：名字 / 在一起日期 / 解锁密码 / 标语 / 问候语
   - **情话与卡片 / 纪念日与时光轴 / 情书与心愿 / 题库与真心话（含每日一问）**：全部列表式编辑，支持增删、上下移动
   - **相册管理**：直接上传照片（自动压缩、存入服务器）、改分类与说明、删除；可管理访客上传的照片
   - **留言与手写情书 / 时间胶囊 / 每日一问的回答**：查看 / 删除服务器上的内容
     （时间胶囊这里能看到未到期的正文，前台在开启日前拿不到）
   - **备份与恢复**：一键下载全部数据（配置+留言+情书+时间胶囊+每日一问+默契度回合+照片记录+管理员账号），随时可恢复。
     恢复时**默认不动当前管理员账号密码**（备份里的旧密码很容易把人锁在门外），需要时会再问一次；
     备份只含照片记录、不含图片文件本身，恢复时会逐条检查文件是否存在，缺失的会跳过并告诉你数量。
     配置/内容里的格式错误会被逐条拦下：整键类型错（如把名字写成字符串）会整项忽略，
     数组里某一条没填完整只会跳过那一条，并在保存提示里告诉你有几条被跳过。
   - **账号设置**：修改密码；高级模式可直接编辑整份 JSON
4. 保存后全站**立即生效**，无需重新构建/上传

访客写入限流（按 IP 分桶，同 wifi 的两个人共用一个额度）：留言/情书/胶囊/每日一问/删除 30 次 / 10 分钟，
照片上传 120 张 / 10 分钟（批量上传一次几十张不会撞墙）；后台登录失败 5 次锁 10 分钟；
**解锁密码失败 10 次锁 10 分钟**。

安全设计：管理员密码用 `password_hash` 加盐存储；登录成功会更换 Session ID，失败 5 次按 IP 锁 10 分钟；
`data/` 目录对浏览器完全不可见（`.htaccess` 拒绝访问，PHP 建目录时会自动生成该保护文件，
不依赖部署脚本）；上传的照片只允许图片格式，且**目录整体禁止直链**（只能走 `photo.php` 代理）；
留言/情书/照片的"归属"由服务端 HttpOnly Cookie 判定，接口不下发任何身份凭据；
解锁密码只存服务器并用 HMAC 签名的 HttpOnly Cookie 维持，改密码即全量失效。

> 🕳️ 一个踩过的坑（写在这里省得以后再踩）：**主机不允许文件名叫 `gate.php`**。
> 实测 InfinityFree 的防护系统会直接掐断对 `/api/gate.php`、`/lib/gate.php` 的请求
> （连接被重置，不是 404）。所以本项目的解锁接口叫 `api/unlock.php`，门禁库叫 `lib/access.php`。

## 🔄 更新部署（不破坏服务器自定义内容）

> ⚠️ **最重要的一条**：以后更新网站，**不要**用 FileZilla 之类"镜像同步/删除多余文件"的方式
> 上传整个目录 —— 那会把服务器上的自定义内容（后台配置、留言、照片）全部删掉！

更新请统一用仓库自带的部署脚本（需要 Python 3，凭据文件放仓库外）：

```bash
python tools/deploy.py --creds "我的服务器\服务器.txt"
```

脚本会：
1. 自动重新构建 `dist/`（版本号自动变化，访客强制拉新文件）
2. 只上传 `dist/` 清单内的文件，**绝不删除远程任何文件**
3. **永远跳过以下保护路径**（它们只属于服务器，由管理员后台维护）：
   - `data/` —— 后台的全部自定义数据（配置/留言/情书/照片记录/管理员账号）
   - `assets/img/uploads/` —— 上传的照片
   - `assets/img/*.jpg / .jpeg / .png / .webp` —— 直接放进服务器的真实照片
     （只在服务器上**还没有同名文件**时补传一次，绝不覆盖）
   - `assets/music/music.dat` —— 背景音乐（旧 `music.mp3` 同样受保护，只留不传）
4. 每次同步 `data/.htaccess`、`assets/img/uploads/.htaccess` 保护模板与根目录 `.htaccess`（幂等）
5. 上传带重试；凭据文件支持 UTF-8 / GBK；**默认要求 FTPS（加密）**，握手失败即停止并提示
   （不再自动回退明文——那等于替你把安全决策做掉了；主机确实不支持时才显式加 `--no-tls`）

原则：**凡是被上传覆盖的文件 = 可替换的"程序"；自定义内容只存在于 `data/` 和 `assets/img/uploads/`**。
照片如果不想走后台上传，也可以手动 FTP 传进 `assets/img/`（部署脚本只在"服务器上还没有同名文件"时
补传一次，绝不会覆盖服务器上的照片；构建脚本会把这些照片打进 `dist/`）。
